## 目的
人間の技術判断を根拠付きで資産化し、開発保守で利用する。[確定: ユーザーの企画説明]
現在の証拠から過去判断の前提を判定し、継承・更新提案・保留を使い分ける。[候補: 直前の議論で提示]

## 対象・範囲
最初は1つの合成リポジトリ相当の事例に絞る。[候補]
実GitHub連携、PR投稿、本番反映、既存2サービスの全面統合は最初の必須範囲にしない。[候補]

## 要件と確認方法
| ID | 要件候補 | 検証 |
|---|---|---|
| R-01 | 過去判断を根拠・前提・承認状態とともに参照する | 出典と現在証拠をたどれる [候補] |
| R-02 | 前提維持時は衝突する変更を指摘する | デモAで継承判定 [候補] |
| R-03 | 前提変化の証拠があれば更新案を作る | デモBで人間確認待ち、資産は未更新 [候補] |
| R-04 | 根拠不足を肯定とみなさない | デモCで不足証拠を提示 [候補] |
| R-05 | 必要に応じて許可ツールで追加証拠を集める | 判断とツール実行の履歴を確認 [候補] |
| R-06 | 実行・検証・モデル・費用の記録を残す | 実測と推定を区別し追跡できる [候補] |
| R-07 | 権限、試行、費用上限に達したら停止する | 境界ケースで新たな呼び出しが行われない [候補] |
| R-08 | テスト削除・検査無効化を修復成功にしない | 禁止差分の拒否 [候補] |
