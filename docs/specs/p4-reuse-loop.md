# 仕様 — 実装資産の再利用ループ (P4)

## 状態

| 項目 | 内容 |
|---|---|
| 対象 | Implementation Asset を1件だけ通す、再利用→検証→資産化→承認→二回目の利用 |
| 版 | 0.1.0 |

| 承認記録 | `docs/approvals/p4.md` |
| 最終更新 | 2026-09-21 |

## 1. 何を作るのか

一回目の開発で得た**動作確認済みの実装**を資産として残し、二回目の課題で
関連する判断を確認したうえで**実際に再利用し、テストで検証し、結果を資産へ戻す**。
人が承認したのち、後続の課題でその資産が使われるところまでを1本通す。 [確定: ユーザー指示]

現在実装済みの「適用可否判定コンポーネント」は、この経路の**判断ゲート**として使う。 [候補]

## 2. これがないと、誰が何に困っているか

現在の実装は、過去判断の前提が成立するかを判定して終わっている。
**判定しても、実際に何かが再利用されるわけではない。**
そのため「二回目の開発が変わる」という構想の中核を確かめる経路が無い。 [確定: ユーザー指摘]

## 3. 今回作らないもの

- UI、自動PR作成、サンドボックス実行、既存2サービスの全面統合 [確定: ユーザー指示「後回しで構いません」]
- 実アプリへの適用（合成事例で通す） [候補]
- 実装資産の自動抽出（OrcaReplay連携）。調査中であり、今回は手動で1件作る [候補]
- 複数の実装資産、資産の検索ランキング [候補]

## 4. 使い方

```
# 二回目の課題に対し、再利用できる実装資産を探して適用し、検証する
$ python -m decision_keeper reuse \
    --assets      tests/fixtures/assets/ \
    --impl-assets tests/fixtures/impl-assets/ \
    --task        tests/fixtures/tasks/T2-export-job/ \
    --repo        tests/fixtures/tasks/T2-export-job/repo/ \
    --out         artifacts/reports/T2.md \
    --propose-asset artifacts/candidates/
```

出力: 適用した実装資産、判断ゲートの結果、生成した差分、テスト結果、資産候補。
終了コード: 0=再利用して検証成功 / 10=再利用したが検証失敗 / 20=再利用しない（判断ゲートで停止） [候補]

## 5. 要件

| ID | 要件 | 確認方法 | 状態 |
|---|---|---|---|
| P4-01 | 実装資産を、目的・適用条件・依存・検証方法とともに参照できる | YAMLを読み、これらのフィールドが揃わないものは読み込まない | [確定] |
| P4-02 | 二回目の課題に対し、適用条件が合致する実装資産を選び、選定理由を残す | T2で1件選ばれ、選定理由が出力に含まれる | [確定] |
| P4-03 | 実装資産を適用する前に、関連する判断資産の前提を検査する | 判断ゲートの結果がレポートに出る。hold なら適用しない | [確定] |
| P4-04 | 判断ゲートが hold のとき、実装資産を適用してはならない | 前提が崩れたT2'で、差分が生成されないことを確認 | [確定] |
| P4-05 | 適用した結果をテストで検証し、成否を記録する | テスト実行の終了コードと出力がレポートに残る | [確定] |
| P4-06 | テストが失敗したとき、成功として記録してはならない | 失敗するT2''で、終了コード10かつ資産候補が「検証失敗」を持つ | [確定] |
| P4-07 | 検証結果を新しい資産候補へ戻す。既存資産は書き換えない | 実行前後で既存資産のSHA-256が不変。候補は別ディレクトリに出る | [確定] |
| P4-08 | 未承認の資産候補は、後続の課題で使われてはならない | 承認前のT3で候補が選ばれないことを確認 | [確定] |
| P4-09 | 人が承認した資産は、後続の課題で実際に選ばれ、再利用される | 承認後のT3で候補が選ばれ、適用されることを確認 | [確定] |
| P4-10 | 一回目と二回目で何が省略されたかを記録する | 探索・比較・実装の各工程について、省略の有無がレポートに出る | [確定] |

## 6. 守らなければならないこと

- 既存の判断資産・実装資産を人の承認なしに更新しない [確定]
- 適用は隔離せずローカルで行うが、**対象は合成リポジトリに限る** [候補]
- テスト削除・検査無効化を検証成功にしない（R-10 と同じ扱い） [候補]
- 分かっている限界: 合成事例1件、実装資産1件での結果であり、一般性は主張しない [確定]

## 7. 判断の分担

- **任せる**: モジュール分割、合成課題T1〜T3の中身、レポート整形、テストの書き方
- **確認する**: Implementation Asset のスキーマ（保存されるデータの形）、
  `reuse` の引数と終了コード、適用の実行方法（差分生成かテンプレート展開か）
