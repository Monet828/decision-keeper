# 企画の引き継ぎ

## 目指すもの
コードの変化を監視し、チームの技術判断を継承・更新する開発保守エージェント。
空き箱が「何を、なぜ、どんな条件で決めたか」を持ち、IgNight的な機能が現在の変更や障害の証拠を集める。エージェントが前提を比較し、継承、見直し提案、保留を選び、許可範囲内で検証・修正する。

## 独創性の仮説
「CIは通るが、チームが守っていた設計を壊している変更」を扱う。過去の判断を固定ルールとして守るだけでなく、その判断を支える前提が変わったかを調べる。市場唯一性は未調査であり主張しない。

## 説明用の合成事例（未実装）
速度改善のため権限に関わる情報をキャッシュする提案。過去の判断には「権限変更を即座に反映するためキャッシュしない」とある。
A: 現在も無効化機構がない → 過去判断を継承し、衝突を指摘。
B: 無効化機構があり、対象経路の検証証拠もある → 過去判断の見直しを提案。自動承認しない。
C: 無効化機構があるという説明だけ → 有効性は未確認。追加検証・相談。
通常CIの成功と、権限反映の正しさの証拠は区別する。合成データから本番安全性を主張しない。

## 判断資産の候補項目
問題、選択、理由、制約・前提、棄却案、適用範囲、見直し条件、出典、検証結果、版、人の承認状態。正式データスキーマは未決。
FACTSとINTERPRETATIONを分ける。PRマージを業務成功と同一視しない。理由不明なら不明とする。

## 現状
コンセプトとデモは議論からの整理。UI・技術・詳細仕様・実装は未承認／未実装。既存2プロジェクトを変更せず、必要な能力の接続を検討する。
