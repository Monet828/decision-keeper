### 判断 DEC-004 v1（現在の再評価: hold）
- 問い: 認証ガードの開閉を左右する設定を、環境変数に置くかコードに固定するか
- 判断: コードに固定する。環境変数には置かない
- 理由: 観測（連携アプリ側に記録された実測。ホスト信頼の環境変数を設定せず next start で起動）: `GET /` が 200 を返しアプリ画面が表示された。`GET /api/posts` は 500 を返した。 機構としては、認証ライブラリが Vercel 以外で Host ヘッダを信頼せず例外を投げ、 その例外が認証ミドルウェアを中断させ、フレームワークはページをそのまま返す。 未ログイン時のサインイン画面への転送が起きない。 Vercel 上では実行環境が付与する環境変数によって自動的に信頼されるため発現しない。 解釈: 認証ガードが fail-open する。開くか閉じるかを決める設定をコードの外に置くと、 設定を忘れた環境で黙って開く。移設・プロキシ越し・プレビュー環境が該当する。
- 棄却案: ホスト信頼を環境変数で有効化する — 設定を忘れた環境で認証が開く。実測で GET / が 200 を返した。 開閉を決めるものをコードの外に置かない
- 棄却案: Vercel に載せて自動信頼に任せる — Remotion のヘッドレス Chromium・ffmpeg・projects/ の永続ディスクがサーバーレスに 載らない（design ##42）。連携アプリが Vercel に載れているのは重い実行時依存が無いため
- 前提の再検証結果（今回このリポジトリで実測した）:
  - C1 [supported] デプロイ先が Vercel ではない（ホスト信頼が実行環境から自動で付与されない） … 1 ファイルを走査し 0 件一致。探索した結果として存在しないことを確認した
  - C2 [not_observed] 認証ガードがミドルウェア層にあり、その層の例外がフレームワーク既定で「通す」側に倒れる … 観測できていない。verifier.type=human は自動確認できない。人の確認が必要
  - C3 [supported] 環境変数だけで認証を素通りさせる分岐が入っていない … 29 ファイルを走査し 0 件一致。探索した結果として存在しないことを確認した
