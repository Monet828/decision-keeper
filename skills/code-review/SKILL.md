# code-review — 監査オーケストレーター

## 役割

`items/*.md` に定義された規約項目を変更差分に一括適用し、違反を検出・是正し、
最終レポートを人間に引き渡す。

**規約の"正本"は AGENTS.md**。この skill は AGENTS.md の規約を items に落として
検査する実行系にすぎない。規約そのものを増やす／変える判断は AGENTS.md 側で行い、
ここには「検査可能な形（grep 等）」で反映する。

この skill は **push / merge / PR を行わない**。結果を人間に渡すだけ
（PR コメントに貼りやすい形で出力する）。実際の push・PR・マージは人間の担当。

## スコープ決定

1. 引数があればそれに従う: パス / glob / `--staged` / `--branch`。
2. 引数がなければ既定 = 作業ツリー + ベースブランチ比較のコミット済み差分。
   ベースブランチは自動検出する:

   ```sh
   base="$(git symbolic-ref --quiet --short refs/remotes/origin/HEAD 2>/dev/null | sed 's#^origin/##')"
   base="${base:-main}"
   git diff --name-only "${base}"...HEAD    # コミット済み差分
   git diff --name-only                     # 未コミットの作業ツリー差分
   ```

3. 変更が無ければ、対象を尋ねて停止する（憶測で全リポジトリを舐めない）。

## 検査の実行

- `items/*.md`（`_TEMPLATE.md` と `README.md` を除く）を全て読み、各項目の
  「検出方法」の `grep -nE` を変更ファイルに対して実行する。
- 判定は **二値（❌ / ✅）**。重大度のグレーディングはしない。
- **(1) の push ガバナンスも必ず検査する**: `items/review-push-governance.md`
  でスクリプト・CI が保護ブランチ直 push や force push を仕込んでいないか確認する。
- スコープが大きい場合は **サブエージェントにファンアウト**（ファイル群／項目群で
  分割）し、結果を集約する。

## 是正ループ（有界）

- 検出した違反を修正 → 再レビュー、を **最大 3 パス**まで。
- **修正で新たな違反を作らない**（是正時に別項目を壊さない）。
- 3 パスで収束しない残件は、自動修正せず **レポートで人間に引き渡す**。

## ノンストップ実行契約

- 実行中は質問で止まらない。方針の判断が必要な事項は **「方針判断要」** として
  最終レポートにまとめて上げる（`items/review-todo-fixme.md` のような
  needs-decision 項目もここ）。
- **破壊的・不可逆な操作**（ファイル削除、履歴書き換え、force push 相当など）
  のみ、実行前に中断して人間に確認する。それ以外は自走する。

## 最終レポート

以下を出力する（PR コメントに貼れる形）:

- **合否**: ✅ 全項目クリア / ❌ 残件あり
- **収束パス数**: 何パスで収束したか（未収束なら「3 パスで未収束」）
- **違反明細**: 各件を
  `{項目名} / file:line — 問題 — 修正方針`
  の形で列挙。
- **方針判断要**: 自動判断しなかった項目（TODO/FIXME、設計上の判断など）。

レポートはここで終わり。**push も PR も作らない**。人間がレビューし、PR に
反映する。
